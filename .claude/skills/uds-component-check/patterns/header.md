# Header

APG 대응 패턴: Landmarks (`https://www.w3.org/WAI/ARIA/apg/patterns/landmarks/`)

**랜드마크와 제목 계층이 핵심이다.** 헤더는 화면의 이름을 알려주는 곳인데, 실제 구현에서는 그냥 텍스트 한 줄로 처리되는 경우가 많다.

---

## 랜드마크

페이지 최상위 헤더는 `<header>`를 쓴다. 이 요소가 `<main>`, `<article>` 등의 하위에 있으면 자동으로 banner 랜드마크가 아니게 되므로, 최상위인지 확인한다.

한 페이지에 banner 랜드마크는 하나여야 한다. 다이얼로그·시트 내부의 헤더는 `<header>`를 쓰되 최상위가 아니므로 문제없다.

## 제목

화면 제목은 **텍스트가 아니라 제목 요소**여야 한다.

```tsx
<h1>{title}</h1>   // 화면 제목
```

`<span className="text-title">`으로 처리되어 있으면 스크린리더가 제목 목록을 만들지 못하고, 사용자가 제목 단위로 이동할 수 없다.

제목 레벨(h1~h6)은 화면 구조에 따라 달라지므로 **prop으로 열어두는 것**이 좋다. 다이얼로그 헤더는 h2일 수도 있다.

```tsx
type HeaderProps = { as?: "h1" | "h2" | "h3" }
```

## 아이콘 버튼

뒤로가기, 닫기, 메뉴, 검색 등. 전부 `aria-label` 필수다.

| 버튼 | 라벨 예시 |
|---|---|
| 뒤로가기 | "뒤로" |
| 닫기 | "닫기" |
| 메뉴 | "메뉴 열기" + `aria-expanded` + `aria-controls` |
| 알림 | "알림" (개수 있으면 "알림 3개") |

**배지·개수 표시가 있으면 라벨에 포함한다.** 시각적으로 빨간 점만 있고 라벨에 반영되지 않으면 그 정보는 전달되지 않는다.

## 뒤로가기의 정체

뒤로가기가 실제로 이전 화면으로 가는 이동이면 `<a>`, 히스토리 조작이면 `<button>`이다. 라우터에 따라 다르므로 실제 동작을 확인한다.

## 고정 헤더

`position: sticky`로 고정할 때:

- 앵커 링크로 이동 시 제목이 헤더 뒤로 숨지 않도록 `scroll-margin-top` 확보
- iOS 노치 대응: `padding-top: env(safe-area-inset-top)`
- 스크롤에 따라 헤더가 변형된다면(축소·투명도) 그 상태 변화가 콘텐츠를 가리지 않는지 확인

## 제목 말줄임

긴 제목이 잘릴 때 `title` 속성이나 전체 텍스트 접근 경로를 남긴다. 시각적으로만 잘리고 DOM에 전체 텍스트가 있으면 스크린리더는 전체를 읽으므로 문제없지만, `text-overflow` 없이 JS로 문자열을 자르면 정보가 사라진다.

## 좌우 슬롯 균형

좌측 뒤로가기 / 중앙 제목 / 우측 액션 구조에서, 한쪽 슬롯이 비면 제목이 중앙에서 밀린다. 빈 슬롯도 자리를 차지하도록 처리되어 있는지 확인한다. 접근성 문제는 아니지만 시스템 일관성 문제다.
