# CTA

APG 대응 패턴: 없음 (화면 하단 고정 영역)

**모바일에서 가장 사고가 잦은 컴포넌트다.** 화면 하단에 고정되면서 다른 콘텐츠를 가리고, 키보드가 올라오면 위치가 무너지고, 홈 인디케이터와 겹친다. 대부분 접근성 문제가 아니라 **레이아웃 문제**로 나타난다.

---

## 고정 방식

`position: fixed`로 하단에 붙이면 스크롤 끝 콘텐츠가 가려진다. 두 가지 중 하나로 해결한다.

- 스크롤 영역 하단에 CTA 높이만큼 여백을 확보한다
- CTA를 스크롤 컨테이너의 sticky 요소로 둔다

가리는 채로 두지 않는다. 특히 약관 동의처럼 마지막 줄을 읽어야 하는 화면에서 치명적이다.

## Safe area

iOS 홈 인디케이터와 겹치지 않도록 하단 여백을 확보한다.

```css
padding-bottom: max(var(--spacing-16), env(safe-area-inset-bottom));
```

토큰만 쓰고 `env(safe-area-inset-bottom)`이 없으면 실제 기기에서 버튼이 인디케이터에 잘린다.

## 키보드 대응

입력 필드가 있는 화면에서 키보드가 올라올 때 CTA가 어떻게 동작할지 정해야 한다.

- 키보드 위로 따라 올라온다 (`interactive-widget=resizes-content` + dvh)
- 또는 키보드가 올라오면 숨는다

정해지지 않은 채로 두면 기기마다 다르게 동작한다. 어느 쪽인지 코드나 주석에 명시되어 있어야 한다.

## 랜드마크

CTA가 화면의 주요 동작이라면 `<footer>` 또는 명확한 컨테이너로 감싼다. 페이지 전체 랜드마크 구조에서 어디에 속하는지가 정해져 있어야 한다.

다이얼로그·시트 내부의 CTA라면 그 컨테이너에 속하므로 별도 랜드마크를 만들지 않는다.

## 상태

| 상태 | 처리 |
|---|---|
| 진행 불가 (필수 입력 미완) | `disabled` 또는 `aria-disabled` + 이유 메시지 |
| 처리 중 | `aria-busy` + 중복 제출 차단 |
| 오류 후 재시도 | 포커스를 오류 지점으로 이동 |

**중복 제출 차단은 반드시 확인한다.** 결제·신청 화면에서 두 번 눌리면 실제 사고가 난다.

## 콘텐츠 위임

CTA는 컨테이너다. 버튼 구성은 ButtonGroup에, 버튼 스타일은 Button에 위임한다. CTA가 버튼 색상을 직접 정하고 있으면 경계가 무너진 것이다.

## 체크리스트

| # | 항목 | 검사법 |
|---|---|---|
| A1 | 고정 시 콘텐츠 가림 방지책이 있음 | 여백 확보 또는 sticky 확인 |
| A2 | `env(safe-area-inset-bottom)` 처리 | `safe-area` 검색 |
| A3 | 키보드 노출 시 동작이 명시됨 | 주석 또는 코드 확인 |
| A4 | 진행 불가 상태에 이유가 전달됨 | `aria-describedby` 검색 |
| A5 | 처리 중 중복 제출이 차단됨 | `disabled`/`aria-busy` + 핸들러 확인 |
| A6 | 랜드마크 위치가 정해져 있음 | `<footer>`/컨테이너 확인 |
| A7 | 버튼 구성·스타일을 하위에 위임함 | variants 확인 |
| A8 | 터치 영역 44px 이상 | 높이 확인 |
